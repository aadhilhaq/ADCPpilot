How to cite

This interface drives other people's programs, and each has its own paper. The run itself works out which ones it used and writes the list into its own folder.

The button, and what it is scoped to

The header says in one line which papers every published result must cite, whatever else the run used: ADCP, AGFR (which builds the affinity maps and the grid target), AutoDockFR and AutoSite. The line is built from the same list as the dialog, so the two cannot disagree, and its How to cite link opens the dialog.

How to cite is in the header and again at the bottom of the page. Opened from the header it lists every program the tool can use. Opened from a finished run it is scoped to that run, read from the run's own settings: a run without MM-GBSA is not given an Amber citation to include, and a run with non-standard residues is given SwissSidechain.

Three formats download from the dialog: .txt to read, BibTeX for LaTeX, and RIS for EndNote, Zotero and Mendeley. They are generated from the same list rather than kept as files, so they cannot drift apart from what the tool actually runs.

In every run folder

Every run carries its own citation files, written beside the results:

FileFor
HOW_TO_CITE.txtreading, and pasting into a methods section
CITATION.bibLaTeX
CITATION.risEndNote, Zotero, Mendeley

They are in the folder because a methods section is usually written months after the run, from the output directory rather than from the repository. The same list comes from the command line:

adcp-pilot cite                 every program this tool can use
adcp-pilot cite RUNDIR          the ones that run used
adcp-pilot cite --bibtex        or --ris

What a typical run has to cite

Every DOI in the list is checked against Crossref or DataCite by adcp-pilot cite --verify, so the entries are not transcribed by hand.

ADCP, AGFR and AutoSite are products of the Scripps Research Institute, and this package is an interface to them rather than a part of them. Cite ADCP, AGFR, AutoDockFR and AutoSite whatever else you cite. The Amber developers ask for the AmberTools paper together with the force field paper.

This interface

The dialog's first entry is the interface itself, with the version you ran. The repository also carries a CITATION.cff, which is what GitHub's Cite this repository button reads. Record the version: the settings a version offers, and what it measures, do change between them.

Acknowledging the facility

Many computing facilities ask to be acknowledged in publications. The text depends on where the work ran, so it is configuration rather than code: set ADCP_ACKNOWLEDGEMENT to your facility's wording and every run records it in its citation files. Setting it in activate.sh on the cluster covers every run started there, from the launcher too. Without one, the file carries a reminder to acknowledge whoever ran the work.

Say what the numbers are. Alongside the citations, a methods section needs the settings: the replicas, the steps, the poses kept, the pH, the box, and whether MM-GBSA ran and with which model. All of it is in the run's job.json, and results.json carries the constants every measured number was computed with.
