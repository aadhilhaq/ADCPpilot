The peptides

One peptide per row, or a whole list pasted or uploaded at once. Each row is checked as you type, and the run cannot start while anything in the list is wrong.

What ADCP accepts

Sequences of 5 to 30 residues, in one-letter code, from the twenty standard amino acids.

B, J, O, U, X and Z are refused: B and Z are the ambiguity codes, J is leucine or isoleucine, X is unspecified, O is pyrrolysine and U is selenocysteine. ADCP builds peptides from a rotamer library keyed on the twenty, and none of these has a rotamer it can build.

The lower limit is real: with three or four residues every replica fails. The upper limit is set by the box rather than by the search, since a 30-mer needs about 48 Å of box against a 60 Å maximum. Above roughly 20 residues the cost estimate, not the limit, is the number to read before you submit.

With ADCP 1.1 installed you can also use non-standard and D amino acids. That has a page of its own: Modified and D amino acids.

Pasting a list

Paste a list opens a box that reads several forms, one peptide per line:

ETFSDLWKLLPEN                  named by its own sequence
p53: ETFSDLWKLLPEN             named p53
>p53                           FASTA, named p53
ETFSDLWKLLPEN
TSFAEYWNLLS,PMI                two columns, either way round
p53,ETFSDLWKLLPEN,head to tail a third column: the peptide's own ring
sequence,name,ring             a header row, if you want to be sure

A two column row split by a tab, a comma or a semicolon works in either order: the field that reads as a sequence is taken as the sequence. Where both could be read as sequences, which ordinary words can be, the capitalisation decides, and a header row settles it for the whole list. Lines starting with # are ignored. Blank lines separate FASTA records.

A third column is the peptide's ring: linear (or none), head to tail (or backbone, or cyclic), or disulfide, in any case and with dashes or not. An empty cell docks the peptide as the run is set. A row with no name may put the ring second, ETFSDLWKLLPEN,head to tail. A header row names the columns in any order, with ring or cyclic for the ring, and a spreadsheet saved as CSV with one is read as it is. A ring that is none of these is never guessed at: the row says what it was given and what the choices are, and nothing from the list is added until it is fixed. See a chain or a ring.

Upload a list does the same with a .txt, .csv, .fasta, .fa or .seq file. It is read in your browser and sent through the same parser, so it works even when the cluster cannot see your file.

Spaces inside a sequence are joined, because sequences are often printed in blocks of ten: ETFSDLWKLL PENNVLSPLP is one peptide.

Add these puts a pasted list in whole, and only when every line is clean. What happens otherwise is below.

What is refused, and why

A pasted list goes in whole or not at all. Every line is read on the server before anything is added. If any line has a problem, nothing is added, the text stays in the box, and the message line says nothing added, then each bad line's name or first letters and what is wrong with it. Fix the lines and press Add these again. When every line is clean, all of them are added, the box closes, and the message line says how many went in.

Rows already in the list are checked on the server as you type, and their reason is written under the sequence. The same messages appear in both places:

A disulfide ring needs two cysteinesthis peptide is to be docked as a ring through a disulfide, by its own Ring or the run's, and has fewer than two C; see below
which is not one of the choicesa ring column gave something other than linear, head to tail or disulfide, or a word for one of them; leave the cell empty to dock the peptide as the run is set
Name a peptide with a colon, not a space. Spaces inside a line are joined, so alpha SWQWWWQPQRDCR reads as one 18 residue peptide, ALPHASWQWWWQPQRDCR, and every letter of it is a residue. The page recognises the shape, a word and then a sequence, and refuses the paste with that reason instead of adding the longer peptide. Write alpha: SWQWWWQPQRDCR, or use FASTA. adcp-dock new refuses such a line in the same way. An uploaded list is different: it is added whole, the message says how many of its rows have something to check, and a line like that among them becomes the longer peptide, so check the residue count under each row.

The same sequence twice is refused, because both rows would share one working directory and one result file. That holds for one sequence with two different rings as well: to compare a peptide as a chain and as a ring, dock the second in a run of its own. Two peptides with the same name are refused for the same reason.

A chain or a ring

A peptide is docked as one of three things:

RingWhat ADCP does
linearthe peptide's two ends are free, as every run before rings could be chosen was docked
head to tailthe first residue's nitrogen is drawn to the last residue's carbon (ADCP's -cyc)
disulfidetwo cysteines' sulfurs are drawn together (ADCP's -cys)

The run docks each peptide as, under the list, is the run's choice, and every row's Ring starts at as the run, which follows it. Set a row's Ring to linear, head to tail or disulfide and that peptide is docked that way whatever the run's choice is, so one run can hold linear peptides and rings of both kinds. The line beside the run's choice says what will happen: when every row is docked the same way it says so, and when the rows differ it names which rows, by the numbers down the side of the list, are docked which way.

Each peptide keeps its own ring from start to finish. Its docking task gives ADCP -cyc or -cys for that peptide alone, and the task's log begins with the ADCP command it ran. MM-GBSA closes that peptide's ring and no other. The estimate prices each peptide's search with its own ring and sizes the walltime for the slowest of them, which can be a shorter peptide closed head to tail. Whenever any peptide in a run was docked as a ring, the results table, results.tsv and results.txt carry a ring column that says how each one was docked.

A peptide list carries rings in its third column, as above, and a row whose ring cell is empty is docked as the run is set. On the command line, --cyclic is the run's choice and the ring column of the file given with -f sets each peptide's own. A run made before peptides could have rings of their own docks every peptide with the run's choice, as it always did.

A ring through a disulfide needs at least two cysteines, C or the D form &C, in each peptide docked that way. One with fewer is refused as you type, in the row's message, and the run cannot be submitted; the command line refuses it the same way, naming the peptide. ADCP itself does not check: given a peptide with one cysteine or none, it docks it as a linear chain and reports poses with no warning, so a run would describe as a ring a peptide that was never closed. A non-standard residue built on the cysteine model, such as C<HCS>, does not count, because ADCP's disulfide joins the atoms named SG and its sulfur is named otherwise.

Both rings are restraints ADCP's search pulls on rather than bonds the peptide starts with. In short test runs on MDM2 the head to tail ring held the two ends 0.4 to 4.0 Å apart in every pose, against 13.7 to 37.9 Å for the linear peptide, with standard, D and non-standard residues alike. The disulfide was less dependable: with a cysteine added at each end of the p53 peptide, the two sulfurs of the top pose were 14.8, 8.3 and 2.8 Å apart in three runs, and most poses were not closed. Check the poses you use. A ring also makes the search longer: each replica took about one and a half times as long head to tail, and the walltime estimate allows for it.

A ring is rescored with MM-GBSA on the poses that close it. The rescoring builds the ring's closing bond, but only on a pose whose two ends already meet: within 2.5 Å for a head to tail ring and 3.5 Å for a disulfide. A pose that is not closed is not rescored and the task log says so, and a peptide with no closed pose among its top poses keeps its docking score and its interface panel and is listed as unranked. See D residues and rings. ADCP 1.1's OpenMM minimisation, in the Docking card, is a separate option: it adds the ring's closing bond too, and for a disulfide only where the two sulfurs are within 3.5 Å of each other.

Helical starts

Each replica of ADCP's search starts the peptide in a shape: a helix or a coil. Replicas that start helical is the share that start as a helix, 25% by default (ADCP's -p). ADCP numbers its replicas and starts the first N × p / 100 of them, rounded down, as a helix and the rest as a coil: at 25% with 50 replicas, replicas 1 to 12. In the MDM2 runs the first frames of replicas 1 to 12 were helical and those of 13 to 50 were not.

ADCP reads the starting shape from the case of the sequence's letters, upper case for helix and lower case for coil, and -p rewrites the case replica by replica, so how a sequence is typed makes no difference. The library names of non-standard residues, in angle brackets, are passed as written. At 0 every replica starts as a coil, which is how every run before this setting was docked, and at 100 every replica starts as a helix. ADCP's -p does nothing at 0 or at 100, so those two are given to ADCP as an all lower case or all upper case sequence instead.

The search is as long either way; only where it starts changes. A peptide that binds as a helix, as p53 does on MDM2, is found from a helical start that a coil would have to fold into first.

Names, and what the list costs

A name is worth giving. It is what appears in the results table and in the pose viewer, and it is what tells two variants of one construct apart. Without one, a pasted peptide is named by its own first letters, and a row you left unnamed becomes peptide_1, peptide_2, and so on.

On a cluster each peptide becomes its own Slurm array task, so twenty peptides are twenty tasks that queue and run independently, and one failing does not lose the others. The run can be resumed, and only the peptides with no result are docked again.

Length drives the cost more than the list does. The search effort should scale with the peptide, so a list of 20-mers is not twice a list of 10-mers but rather more. The estimate under the resources row works this out from your longest peptide.
