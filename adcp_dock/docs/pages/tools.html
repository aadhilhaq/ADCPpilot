Optional tools

Docking needs four programs. Everything on this page is extra: each one adds something, and the page tells you which of them it can see.

What is installed here

The line at the top of the page says whether the required programs were found, and how many optional ones are missing. For the full answer, ask the installation directly:

adcp-dock check

It prints every program it looks for, the path it found, and what each missing one would have been used for. Required are adcp, agfr, prepare_receptor and pdb2pqr; the rest of this page is optional.

AmberTools, for MM-GBSA

tleap, sander, MMPBSA.py and ante-MMPBSA.py are what compute the energies. Without them the Rescore with MM-GBSA box is switched off and disabled, and the page says why. Docking works normally; the table is then ranked on ADCP's own score.

AmberTools is not on PyPI, so it comes from conda:

conda install -c conda-forge ambertools

Point AMBERHOME at the environment that has it, or pass --tools-root, and check with adcp-dock check. What the rescoring then does is described in Rescoring with MM-GBSA.

ADCP 1.1

ADCP 1.1 is the current version of AutoDock CrankPep. It adds non-standard and D amino acids, all-atom poses in one file, and an optional OpenMM minimisation and re-ranking of the top poses. Scripps distributes it as its own Python 3.7 environment:

adcp-dock install-adcp11

This follows Scripps' own installation recipe: it creates the environment with micromamba, installs OpenMM, Open Babel and PDBFixer from conda-forge, and fetches the Scripps packages, checking each against a pinned checksum. It takes about ten minutes and 3 GB. ADFRsuite 1.0 is still needed, for the receptor preparation and the grid maps.

Once it is installed, Docking engine offers it, and newest installed picks it. The interface looks for it at $ADCPSUITE_HOME, in a folder named adcpsuite beside ADFRsuite or in a tools folder given with --tools-root, at ~/.adcp-dock/adcpsuite, or at /content/adcpsuite in Colab. What it lets you dock is in Modified and D amino acids.

Some components of Scripps' ADCP 1.1 environment are free for academic use only. The repository's third party notices say which.

ADapt

ADapt, by Michel Sanner, is a separate program, not part of this package. It runs on the ADCP 1.1 environment above. Get it with:

git clone https://github.com/michelsanner/adapt

When the interface finds both ADapt and ADCP 1.1, the Receptor card shows Open ADapt, which opens it in a new tab. Its first start imports AGFR's libraries and can take a minute or two on a busy login node, so the interface starts it in the background as soon as the page shows the button, and the tab says what it is waiting for. ADapt keeps its sessions in a folder inside your runs folder, and it stops when the interface stops.

It comes through this interface's own connection, under /adapt/, so nothing else needs forwarding.

Use ADapt to look, and this interface to prepare. ADapt protonates with reduce, as AGFR does, and the preparation here uses pdb2pqr with PROPKA at your pH; the two often place histidine hydrogens differently. Decide what to keep in ADapt, then let this interface prepare the receptor, so the docking and the rescoring use the same hydrogens. See Histidines at the site.

PDBFixer, OpenMM and Biopython

These three do the receptor repair work: PDBFixer rebuilds missing side chains and loops, OpenMM runs the restrained minimisation, and Biopython reads mmCIF files. They install with the package's prep or local extra.

They are optional in the sense that the run continues without them, but the preparation log then says which steps it had to skip, and a receptor that was not minimised is a receptor docked with unrelaxed hydrogens. Install them.

Schrodinger Prime

If your site licenses the Schrodinger suite, Prime appears as a third MM-GBSA engine. It is found at $SCHRODINGER or in the usual places a site install lives, including the module system, so a batch job that does not load the module can still find it.

Prime uses OPLS with VSGB 2.0, a different force field and a different solvent model from AmberTools, so its numbers are on their own scale: on one test pose AmberTools gave -48.07 and Prime -81.79. It writes its own columns and is never merged with or compared against the others by value.

A target file from AGFR

A run can start from a target file made in AGFR or AGFRGUI, given under or a target file in the Receptor card. Its receptor, maps and box are used as they are, and this package's receptor preparation does not run, so every choice about chains, protonation and heteroatoms was made in AGFR instead.

Do not rename the file: ADCP finds the maps by its name. If the target turns out to be truncated or built from another structure, the run says the target is unusable rather than docking into empty maps.
