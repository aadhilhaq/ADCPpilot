Optional tools

Docking needs four programs. Everything on this page is extra: each one adds something, and the page tells you which of them it can see.

What is installed here

The line at the top of the page says whether the required programs were found, and how many optional ones are missing. For the full answer, ask the installation directly:

adcp-dock check

It prints every program it looks for, the path it found, and what each missing one would have been used for. Required are adcp, agfr, prepare_receptor and pdb2pqr; the rest of this page is optional.

AmberTools, for MM-GBSA

tleap, sander, MMPBSA.py and ante-MMPBSA.py are what compute the energies. Without them the Rescore with MM-GBSA box is switched off and disabled, and the page says why. Docking works normally; the table is then ranked on ADCP's own score.

AmberTools is not on PyPI, so it comes from conda:

conda install -c conda-forge ambertools

Point AMBERHOME at the environment that has it, or pass --tools-root, and check with adcp-dock check. What the rescoring then does is described in Rescoring with MM-GBSA.

ADCP 1.1

ADCP 1.1 is the current version of AutoDock CrankPep. It adds non-standard and D amino acids, all-atom poses in one file, and an optional OpenMM minimisation and re-ranking of the top poses. Scripps distributes it as its own Python 3.7 environment:

adcp-dock install-adcp11

On a cluster, install.sh runs this for you, and stops if it fails. It follows Scripps' own installation recipe: it creates the environment with micromamba, installs OpenMM, Open Babel and PDBFixer from conda-forge, and fetches the Scripps packages, checking each against a pinned checksum. It takes about ten minutes and 3 GB. The suite is all the docking needs: its own adcp, agfr, prepare_receptor and reduce, and MSMS as its library, mslib, for the surfaces. ADFRsuite 1.0 is needed only for the ADCP 1.0 and AGFR 1.0 choices, and install.sh --with-adfr10 adds it; an installation that already has it keeps using its prepare_receptor, reduce and msms. Where only ADFRsuite 1.0 is installed, the Docking card says so plainly: runs then use ADCP 1.0 and AGFR 1.0.

The suite carries its own AGFR, newer than ADFRsuite's, and the grid maps are built with it wherever the suite is installed: AGFR, newest installed under Grid maps in the Site card. It is found with ADCP 1.1, from the same installation, so wherever one is, so is the other. It offers AutoSite 1.1, adds the receptor gradient only when asked, and can place the box around an AutoSite pocket; see the grid maps. ADCP 1.0 docks into its maps as well as ADFRsuite's.

Once it is installed, Docking engine offers it, and newest installed picks it. The interface looks for it at $ADCPSUITE_HOME, in a folder named adcpsuite beside ADFRsuite or in a tools folder given with --tools-root, at ~/.adcp-dock/adcpsuite, or at /content/adcpsuite in Colab. What it lets you dock is in Modified and D amino acids.

Some components of Scripps' ADCP 1.1 environment are free for academic use only. The repository's third party notices say which.

ADapt

ADapt, by Michel Sanner, is a separate program, not part of this package. It runs on the ADCP 1.1 environment above. On a cluster, install.sh and update.sh fetch it from its repository, https://github.com/michelsanner/adapt, into a folder named adapt beside ADFRsuite, and update.sh keeps it up to date. They fetch it anonymously, never asking for a password, so while the repository is private they say so in one line and carry on, and the first update after it becomes public brings it in. An update that would leave an ADapt this interface cannot embed is undone, and a checkout with local changes or on another branch is left as it is. With access to the repository now, clone it beside ADFRsuite yourself:

git clone git@github.com:michelsanner/adapt.git "$(dirname "$ADFRSUITE_HOME")/adapt"

When the interface finds both ADapt and ADCP 1.1, ADapt opens by itself in a frame in the Receptor card on each structure loaded there; Open full screen shows the same session in a tab of its own, and on a phone a button opens it in a tab instead. Change anything in it and the receptor as set there is the one docked: ADapt writes it when you submit, and it is read back and recorded with the run (see a receptor prepared in ADapt). Its first start imports AGFR's libraries and can take a minute or two on a busy login node, so the interface starts it in the background as soon as the page opens, and the card says what it is waiting for. ADapt keeps its sessions in adapt_sessions inside your runs folder, and it stops when the interface stops.

It is embedded the way its own README describes. It is started with --base-path /adapt and its page uses relative paths only, so this interface's server passes /adapt/ to it unchanged, over the connection the page already has, and nothing else needs forwarding. The structure is handed to it through its api/upload, or its api/fetch for an entry fetched by its id, and the frame is opened with session= in the address. What has been changed is read from the session.json ADapt rewrites after every edit; the receptor is written through its api/save, the call its own receptor PDBQT button makes; and the save is read from the session folder it wrote. This needs ADapt from commit 6dae90b on; an older checkout is not offered, and the card says how to update it: ./update.sh does.

reduce and MSMS, from ADFRsuite

Two more programs are taken from ADFRsuite's own bin folder, beside prepare_receptor, and nowhere else, since they are the ones ADFR's own preparation and ADapt use:

  • reduce places the receptor's hydrogens, by default (see protonation), and names each complex's histidines for MM-GBSA in such a run. Without it the receptor is protonated with PDB2PQR and PROPKA instead.
  • MSMS computes the molecular surfaces the site view and the pose viewer draw (see the surface). Without it the viewers draw their own. Its licence allows non-commercial scientific research only, so it is called as the program installed with ADFRsuite and is not copied into this package; the repository's third party notices say more.

adcp-dock check lists both with the path it found.

PDBFixer, OpenMM and Biopython

These three do the receptor repair work: PDBFixer rebuilds missing side chains (unless that is turned off) and loops, OpenMM runs the restrained minimisation, and Biopython reads mmCIF files. They install with the package's prep or local extra.

They are optional in the sense that the run continues without them, but the preparation log then says which steps it had to skip, and a receptor that was not minimised is a receptor docked with unrelaxed hydrogens. Install them.

Schrodinger Prime

If your site licenses the Schrodinger suite, Prime appears as a third MM-GBSA engine. It is found at $SCHRODINGER or in the usual places a site install lives, including the module system, so a batch job that does not load the module can still find it.

Prime uses OPLS with VSGB 2.0, a different force field and a different solvent model from AmberTools, so its numbers are on their own scale: on one test pose AmberTools gave -48.07 and Prime -81.79. It writes its own columns and is never merged with or compared against the others by value.

A target file from AGFR

A run can start from a target file made in AGFR or AGFRGUI, given under or a target file in the Receptor card, where Load checks it and shows its receptor and box in the site view, and Browse lists target files. Its receptor, maps and box are used as they are, and this package's receptor preparation does not run, so every choice about chains, protonation and heteroatoms was made in AGFR instead. See a target file from AGFR.

Do not rename the file: ADCP finds the maps by its name. If the target turns out to be truncated or built from another structure, the run says the target is unusable rather than docking into empty maps.
