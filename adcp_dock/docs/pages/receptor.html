The receptor

Load the protein you are docking into, keep the chains you want, and let the preparation turn a crystal structure into something a force field will accept.

Loading a structure

There are four ways in, and they end in the same place.

  • PDB id. Four characters, such as 1YCR. The file is fetched from the RCSB and cached, so each id is downloaded once per machine. This needs the internet, which a compute node usually does not have.
  • A file already on this machine. A .pdb, .cif, .mmcif or .ent file, gzipped or not. Nothing is copied: the path is read where it is, so it must be somewhere the compute nodes can see too. Browse walks the cluster's folders.
  • From this computer. Reads a file on the machine your browser is on and sends it through the connection that is already open. Use this when the cluster cannot see your file.
  • A target file made in AGFR or AGFRGUI (.trg). Its receptor, maps and box are used as they are, and none of the preparation below runs. See a target file from AGFR.
  • A receptor prepared in ADapt. Load a structure by any of the first three and ADapt opens on it in the card. Change there what stays in the receptor, and that receptor is docked. See a receptor prepared in ADapt.

A .pdbqt is not taken by any of the first three. It is a receptor already prepared for AutoDock, and this tool prepares its own from a PDB or mmCIF file; nothing here builds maps from a PDBQT as it stands. To dock into a receptor you prepared yourself, make a target file from it in AGFR or AGFRGUI and give that.

An mmCIF is converted to PDB with OpenMM before anything else, because every later step reads fixed-column PDB.

Once a structure is loaded, the chain boxes appear. Tick the chains you want to dock against; none ticked keeps them all. A structure solved with its partner bound, as 1YCR is, usually wants only the receptor chain: see A site between two chains.

A backbone trace is not prepared. One atom per residue means every side chain is missing, and rebuilding them all is modelling rather than preparation. The preparation stops with that message at the start of the run.

What preparation does

Its settings are in the Receptor card, under the chains, as one group in the order they are applied: Keep heteroatoms, Rebuild missing side chains, Rebuild missing loops, Protonate with (reduce, or PROPKA at a pH) and Minimise the receptor after protonation.

The preparation runs as the first job of the run, not while you are typing. Every step is logged in receptor/preparation.log inside the run, and the results page reads that log back, so a step that was skipped is visible afterwards. In order:

  1. Bibliographic header records are dropped, because later steps trip over them.
  2. The chains you kept are kept and the rest dropped.
  3. One conformer per atom where there are alternate locations: the highest occupancy, ties to the first. Docking against both copies is docking against a protein that does not exist.
  4. Modified residues that stand in for an ordinary one are read as that one: selenomethionine as methionine, phosphoserine as serine, and so on.
  5. Waters are removed.
  6. Other heteroatoms are removed unless you keep them. See heteroatoms.
  7. Disulphides within 2.5 Å are found and named in the log, so you can see which cysteines are paired. pdb2pqr works them out for itself.
  8. Missing atoms are rebuilt and the termini capped, so a chain break is not read as a charged terminus. Missing side-chain atoms can be left out of the result instead: see side chains. Whole missing residues are left alone unless you ask for them: see loops.
  9. Hydrogens, by reduce or by PDB2PQR with PROPKA at your pH: see protonation.
  10. A restrained minimisation: see minimisation.

Then prepare_receptor writes the PDBQT and agfr builds the grid maps over your box (see the grid maps). The example's log reads, in part, kept chain A, dropped B, rebuilt 0 side-chain atom(s), completed 1 terminal atom(s); LEFT 24 missing residue(s) alone and 743 hydrogens added, which is the kind of summary to read before trusting a run.

Protonation: reduce, or PROPKA at a pH

Protonate with chooses the program that places the receptor's hydrogens, and with them decides each histidine and which way round each Asn and Gln amide sits.

reduce is the default because it places histidine protons better. Checked against the protein structures in the PDB solved by neutron diffraction, where the hydrogens are seen, reduce placed the histidine protons as deposited in 55% of 1,457 histidines and PDB2PQR with PROPKA in 31%, and reduce turned fewer rings and amides the wrong way. What reduce does not do is pH: it never protonates an Asp or Glu, and it rarely puts protons on both nitrogens of a histidine. Choose PROPKA at a pH when the pH is part of your question, an endosomal target at 5.5 for example. 7.4 is the default pH.

The log line says what was decided: protonation: done; reduce.3.23.130521 -BUILD, as ADFR and ADapt run it, with -Nterm25 so each chain's first residue is a terminus; 743 hydrogens added; histidines HIE x2; nothing turned over for the example's MDM2, whose chain starts at residue 25. reduce's own record of every decision, one line per histidine, Asn and Gln, is at the top of receptor/protonated.pdb. Where reduce cannot run, PDB2PQR with PROPKA protonates the receptor instead, and the results page says so.

MM-GBSA keeps the choice. Under reduce its complexes take the receptor's own histidine states, named HID, HIE or HIP from where reduce put the protons, and reduce protonates the peptide in the complex. Under PROPKA each complex is protonated again at the same pH, as it always was. Runs made before this choice existed were protonated with PDB2PQR and PROPKA, and reuse settings on one of them sets PROPKA again, so it reproduces. What a site with histidines in it calls for is worth a page of its own: Histidines at the site.

Minimising after protonation

Minimise the receptor after protonation runs a restrained minimisation: the heavy atoms are held near their measured positions at 10 kcal/mol/Å² while the new hydrogens and any clashes relax.

Leave it on. Hydrogens are placed by geometry and have not been relaxed against the force field, so docking without this docks into strain that is not really there. It takes under a minute for a few hundred residues. In the example it moved the heavy atoms 0.11 Å RMSD and took the energy from -2,620 to -3,295 kcal/mol, which is what a working restrained minimisation looks like: a large energy change and almost no movement.

Heteroatoms

Cofactors, ligands, metals and everything else that is not protein are removed unless you tick Keep heteroatoms.

Tick it when what is bound there is part of the site: a structural zinc, or a haem your peptide has to sit against. Leave it off for a crystallisation additive, or for a ligand you intend to displace.

Keeping heteroatoms skips the minimisation. The force field has no parameters for most of what this keeps, metal ions included, so the minimisation cannot run and the results page says so. You are choosing between a site that is complete and a structure that has been relaxed.

Rebuilding missing side chains

Many structures lack the ends of some side chains, usually lysines, arginines and glutamates on the surface, where the density was too weak to place them. Rebuild missing side chains is on by default: PDBFixer rebuilds the missing atoms from a template, they are protonated and minimised with the rest, and the peptide is docked against them. Every run made before this setting existed did the same.

Turn it off when a rebuilt side chain would sit in your site and you would rather dock against what was measured. The receptor that is docked into then carries only the side-chain atoms the structure had.

Off with reduce and no minimisation, nothing is modelled. reduce places hydrogens on a residue as it stands, so the missing atoms are never built. The minimisation's force field has no template for an incomplete residue, and pdb2pqr completes any residue it is given, so with the minimisation on, or with PROPKA chosen, the missing atoms are built for a moment, protonation and minimisation run on whole residues, and then those atoms and the hydrogens on them are taken out. The preparation log names the residues on its side chains line. MM-GBSA builds a complex of its own and needs whole residues too, so the rescoring completes them again there.

Rebuilding missing loops

Rebuild missing loops is about whole missing residues, the stretches the structure never resolved. Missing side-chain atoms have their own setting, above. It is off by default.

A rebuilt loop is a model, and once it is written into the file it looks exactly like a measured one. Turn it on only when a gap sits against your site and leaving a hole there would be worse than filling it. The example leaves 24 missing residues alone, in two stretches well away from the p53 groove, which is the ordinary case. A loop is built from whole residues, side chains included, whichever way the side-chain setting is.

What is built, and what is not:

  • Gaps inside a chain, of up to 12 residues. A longer one is left open and named in the preparation log.
  • Never the residues missing from either end of a chain. The sequence records list them, but they are missing because they are disordered. Built, they come out as a long straight strand lying across the solvent, which can reach into the docking box and offer the peptide a surface that is not there.
  • Never a gap that is only a skipped number, where the residues either side are in fact bonded.

Each built loop is relaxed before the receptor is protonated. The loop moves freely, the two measured residues at each end may give slightly on a spring so it can close, and every other atom stays where it was measured. Then every join between the loop and the measured chain is checked: the bond and both backbone angles must be in range. If a loop cannot be made to fit after several attempts, the preparation stops and the log says which join failed. Untick the setting to dock the structure as measured. The final minimisation leaves built loops free too, since nobody measured them.

A receptor prepared in ADapt

ADapt, by Michel Sanner, shows what a structure file holds and prepares the receptor the way AGFR does, with AGFR’s own code. Use it when the choice of what stays in the receptor matters: which biological assembly, which hetero groups stay (a lone catalytic zinc, for example), the charge a metal carries, which alternate location of a residue, and modified residues.

Where ADapt is installed, it opens by itself, in a frame at the foot of the Receptor card, on every structure you load: a PDB id fetched, a file on the cluster or one from your own computer. Nothing changes by opening it. Its tree lists everything in the file with a tick for what goes into the receptor, and its view shows the structure, with what is in the receptor drawn apart from what is not.

A first start on a busy login node takes a minute or two; later ones are quick. While it starts, the space the frame will fill shows the steps as they happen: ADapt started on the cluster, ADapt answering, the structure handed to it, and its view drawn. Nothing waits on it, so carry on with the site and the peptides meanwhile. If ADapt does not start, the card says why in plain words, with Try again. Docking does not need ADapt: without it, this page prepares the receptor itself.

The line above the frame always says which receptor will be docked.

  • Docking will use this page’s preparation. Until you change anything in ADapt, the run prepares the structure as the settings above say, exactly as it would without ADapt.
  • Docking will use the receptor as set in ADapt. From the first change in ADapt, an unticked chain or the waters taken out for example, the line says so and names the assembly and the last changes. The preparation settings and the chain ticks are greyed out, because ADapt and AGFR decide them now.

You do not need ADapt’s own save button. When you submit, ADapt is asked to write the receptor as it is set there, just as its receptor PDBQT button would, and the receptor is read back and recorded with the run. Use ADapt’s receptor now does the same at once, so the site can be checked on the receptor that will be docked: the site view then shows it. Changing anything in ADapt afterwards means it is written again when you submit. If you do press ADapt’s own save button, that save is read back too.

Once the receptor ADapt wrote has been read back, a card above the frame says Docking will use ADapt’s receptor, with the save, the chains, the hetero groups kept and the changes made in ADapt as short labels, and the rest, such as each histidine’s protonation and the session folder, under Details. It offers only what its state calls for:

  • Up to date with ADapt, with a tick: there is nothing to press.
  • Changed in ADapt since save 1: Use ADapt’s current receptor has ADapt write it again and reads it back. Submitting does the same by itself.
  • Save 2 not read yet: a save made with ADapt’s own button is read back by itself, and if that fails the card says why, with Read save 2 to try again.

Use this page’s preparation instead goes back to this page’s preparation of the structure ADapt was opened on, and the settings above apply again. Only a later change in ADapt brings its receptor back.

Hide folds the frame away; ADapt keeps what you set and the line still says which receptor will be docked. Open full screen shows the same session in a tab of its own, which is easier for a large structure; what you change there counts here, and the frame catches up when you come back. Opened while ADapt is still starting, the tab shows the same steps and goes to ADapt when it is ready. On a phone the frame would be too narrow for ADapt’s tree beside its view, so the card shows an Open in ADapt button instead, which opens ADapt in a tab of its own on the same structure. ADapt reads PDB files; an mmCIF fetched by its id is opened there by the id, and an mmCIF file without one is not opened.

What is read back is what ADapt wrote in its session folder: the receptor PDBQT, which is docked as it is; its _rec_H.pdb, the same receptor with every hydrogen reduce placed, which the site, the viewers and MM-GBSA read; and session.json, which records every change made and every save. The run copies all three into its receptor folder and records the session folder, the save and the files’ checksums in job.json, so a save changed later is refused rather than docked into, and reuse settings reads the same save back and opens ADapt on it again. Nothing of this package’s preparation runs on it: no rebuilt side chains, no minimisation, and reduce placed the hydrogens in ADapt. From the command line the same is adcp-dock new RUN --adapt-session FOLDER [--adapt-save N] -s ....

Where ADapt is missing or too old. Without ADapt the card has no frame and nothing else changes. An ADapt older than the version this interface works with is not opened; one quiet line in the card says how to update it.

A target file from AGFR

A target file (.trg) made in AGFR or AGFRGUI holds a receptor that was already prepared, the grid maps computed from it and the box they cover. Give one under or a target file made in AGFR or AGFRGUI: type its path and press Load, or find it with Browse, which lists only target files.

Loading it checks the file the way the run will: that it is a complete archive, that it holds the maps and a receptor, and that the folder inside still carries the file's own name. A file that fails says why, under the box, and the run cannot be submitted with it. One that passes is shown in the Site card: its receptor, with its box drawn over it as a cage.

The run then takes all three from the file. The preparation settings and the site residues are not used, so they are not asked for when you submit. Do not rename the file: ADCP finds the maps by its name.
