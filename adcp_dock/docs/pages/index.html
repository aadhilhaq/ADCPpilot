GUI to ADCP Docking

Dock peptides into a protein with ADCP, from one page in your browser: prepare the receptor, place the box, paste the sequences, submit, and read the ranked results with the poses.

What it does

You give it a receptor structure and a list of peptide sequences. It prepares the receptor, builds the grid maps around the site you nominate, docks every peptide with ADCP, can rescore the poses with MM-GBSA, and writes a ranked table with the structures beside it.

The search itself is ADCP, a product of the Scripps Research Institute, with the grid maps and the PDBQT files from ADFRsuite. This page is an interface to them: it makes the choices explicit, checks them before anything is submitted, and keeps a record of what each run did. The energies come from AmberTools.

The work does not run in the page. On a cluster each stage is a Slurm job, so you can close the browser and come back. On one machine the same stages run in order, one after another.

The page

  1. The header: what this is an interface to, who wrote it, and the addresses to write to.
  2. Docs, in the top right corner, opens this documentation.
  3. Under the title: How to cite lists every program a run used. Send feedback collects the version and the machine for a report. Dark switches the colours, in the interface and in these pages.
  4. The word beside those buttons: ready when the programs it needs were found, or the names of the ones that are missing.
  5. Receptor: a PDB id to fetch from the RCSB, or a path to a file the cluster can already see, or a file sent from your own computer.
  6. Or a target file made in AGFR or AGFRGUI, which brings its own receptor, maps and box, and skips the preparation here.
  7. Open ADapt, shown when ADapt is installed beside this: it shows what a structure file holds before you dock into it.
  8. Site: the residues the box must cover, the padding around them, and the smallest and largest the box may be.
  9. Check site reports the box it would build, its centre and its size, and says if it reaches a chain you did not load.
  10. The structure, once one is loaded, with the box drawn as a cage. Click a residue to add it to the site, click it again to drop it.
  11. The sequence beside it does the same, residue by residue, for a site you know by number rather than by eye.
  12. The ? beside any label opens what that setting does, with a link into these pages.
  13. The bar along the bottom: the version, the copyright, and the programs that do the work.

The path through a run

  1. Load the receptor and keep the chains you want to dock against.
  2. Name the site, check the box it builds, and look at the cage.
  3. Add the peptides, one per line or pasted as a list.
  4. Set the search: how many replicas, how many steps each, how many poses to keep, and whether to rescore with MM-GBSA.
  5. Ask for resources, name the run, choose where it is written, and submit.
  6. Follow it in the Runs card, then open it and read the table.

Everything a run produces stays in its own folder: the prepared receptor, the grid maps, the poses, the energies, the logs and the citation files. You can reopen a finished run at any time, or download it.

There is a finished run to look at first. adcp-dock example adds one: MDM2 with three peptides, docked and rescored. Open it and read the table before you dock anything of your own. It is the run most of the pictures in this documentation come from.
