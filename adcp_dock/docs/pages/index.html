GUI to ADCP Docking

Dock peptides into a protein with ADCP, from one page in your browser: prepare the receptor, place the box, paste the sequences, submit, and read the ranked results with the poses.

What it does

You give it a receptor structure and a list of peptide sequences. It prepares the receptor, builds the grid maps around the site you nominate, docks every peptide with ADCP, can rescore the poses with MM-GBSA, and writes a ranked table with the structures beside it.

The search itself is ADCP, a product of the Scripps Research Institute, with the grid maps from AGFR and the PDBQT files from ADFRsuite. This page is an interface to them: it makes the choices explicit, checks them before anything is submitted, and keeps a record of what each run did. The energies come from AmberTools.

The work does not run in the page. On a cluster each stage is a Slurm job, so you can close the browser and come back. On one machine the same stages run in order, one after another.

The page

  1. The header: what this is an interface to, the papers a published result must cite, who wrote it, and the addresses to write to.
  2. Docs, in the top right corner, opens this documentation.
  3. Under the title: How to cite lists every program a run used. Send feedback collects the version and the machine for a report. Dark switches the colours, in the interface and in these pages.
  4. The word beside those buttons: ready when the programs it needs were found, or the names of the ones that are missing.
  5. The steps across the top: Receptor, Site, Peptides, Docking and Submit. A number fills green with a tick when its step is done. Click one to go to its card. How each step is decided is below.
  6. Receptor: a PDB id to fetch from the RCSB, or a path to a file the cluster can already see, or a file sent from your own computer.
  7. Under the chains, the receptor preparation: heteroatoms, missing side chains and loops, the pH and the minimisation, in the order they are done.
  8. Or a target file made in AGFR or AGFRGUI, which brings its own receptor, maps and box, and skips the preparation here.
  9. Open in ADapt, shown when ADapt is installed beside this: it opens the receptor in ADapt, where you choose what stays in it, and the receptor you save there is read back and docked as ADapt wrote it.
  10. Site: the residues the box must cover, the padding around them, and the smallest and largest the box may be.
  11. Check site reports the box it would build, its centre and its size, and says if it reaches a chain you did not load.
  12. The structure, once one is loaded, with the box drawn as a cage. Click a residue to add it to the site, click it again to drop it.
  13. The sequence beside it does the same, residue by residue, for a site you know by number rather than by eye.
  14. The ? beside any label opens what that setting does, with a link into these pages.
  15. The bar along the bottom: the version, the copyright, and the programs that do the work.

The steps across the top

The strip follows the checks the page already makes. Nothing turns green because a card was looked at or a number was clicked.

StepDone when
1 Receptora structure is loaded from the path in its box, or a target file is loaded and accepted, since a target file brings its own prepared receptor
2 Sitethe site is checked, in whichever way the box is built: around the residues you pick, around a ligand or peptide, or around an AutoSite pocket, which is found once the receptor is prepared. A target file brings its own box, so it completes this step too
3 Peptidesthere is at least one peptide and every row is accepted. One refused row keeps the run from being submitted, so it keeps this step open as well
4 Dockingevery search setting is inside its limits. The defaults already are, so this step is marked done once the three before it are
5 Submitthe run is submitted. Change anything in the form afterwards and the step opens again, because that is a new run to submit

The card for the first step that is not done is lit, finished cards are green, and the cards after it are grey. Grey is only a hint. Every card can be used at any time, in any order: a target file completes the first two steps at once, and reuse settings on an old run fills four.

The path through a run

  1. Load the receptor and keep the chains you want to dock against.
  2. Name the site, check the box it builds, and look at the cage.
  3. Add the peptides, one per line or pasted as a list.
  4. Set the search: how many replicas, how many steps each, how many poses to keep, and whether to rescore with MM-GBSA.
  5. Ask for resources, then name the run, choose where it is written, and submit.
  6. Follow it in the Runs card, then open it and read the table.

Everything a run produces stays in its own folder: the prepared receptor, the grid maps, the poses, the energies, the logs and the citation files. You can reopen a finished run at any time, or download it.

There is a finished run to look at first. adcp-dock example adds one: MDM2 with three peptides, docked and rescored. Open it and read the table before you dock anything of your own. It is the run most of the pictures in this documentation come from.
